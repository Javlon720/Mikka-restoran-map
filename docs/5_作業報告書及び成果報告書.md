## 1. プロジェクト目標と達成状況
本プロジェクトでは、ウズベキスタン国内の多言語ユーザーおよび外国人向けに、飲食店情報と口コミを共有し、地図とAIアシスタントを組み合わせて直感的に店舗を探せるWebアプリケーション「Mikka」の開発を目標としました。

提出期日である **2026年6月30日** 時点における、要求機能の達成状況は以下の通りです。

| 要求機能 | 開発目標 | 達成状況 | 備考 |
| :--- | :--- | :--- | :--- |
| **飲食店情報管理** | 管理者が店舗のCRUD操作を直感的に行えること。画像アップロード対応。 | **100% 達成** | 管理者専用UIとバックエンドでのMulterによるファイル保存を統合。 |
| **口コミ機能** | 評価、テキスト、画像投稿。自身の投稿の編集・削除。他人の投稿制限。 | **100% 達成** | レビューごとのCRUD処理、星評価の自動集計を実装。 |
| **多言語対応 (i18n)** | 4言語（ウズベク語・英語・ロシア語・日本語）の切り替え。 | **100% 達成** | 自作の `i18n.js` ライブラリによるSPA動的翻訳。 |
| **地図情報連携** | 地図（Leaflet）に店舗情報をマッピングし、クリックで詳細を表示。 | **100% 達成** | 緯度・経度のピン連携、ポップアップからのモーダル展開。 |
| **AIアシスタント連携** | 自然言語でのおすすめ店検索、Gemini APIを利用。 | **100% 達成** | チャットウィジェット、プロンプトチューニングによる店舗レコメンド。 |

## 2. 技術的な取り組みとアプローチ

### 2.1 クリーンアーキテクチャの採用
バックエンドのコードベースにおいて、**クリーンアーキテクチャ (Clean Architecture)** を導入しました。
ビジネスロジック（Use Cases）をデータベース操作（Adapters）やWebフレームワーク（Fastify）から完全に分離することにより、将来的なデータベースの変更（例: PostgreSQLからMongoDBへの移行）やフレームワークの載せ替えに対して、極めて高い保守性とテスト容易性を確保することに成功しました。

### 2.2 インタラクティブな地図表示と緯度・経度選択
ただ地図にピンを表示するだけでなく、管理者が店舗を登録・編集する際に、**専用のモーダル地図上でピンをドラッグすることで自動的に緯度・経度の値がフォームに入力される機能**を実装しました。これにより、専門的な知識がない店舗登録者でも、直感的に正しい位置情報を入力することが可能です。

### 2.3 RAG (Retrieval-Augmented Generation) ライクなAIアシスタント
Gemini APIをただ呼び出すのではなく、**データベース内の最新の飲食店一覧と口コミデータをコンテキストとしてプロンプトに動的に注入**する設計を採用しました。これにより、AIが「架空の店」を案内すること（ハルシネーション）を防ぎ、プラットフォーム上に実在する最新の店舗のみをユーザーの好みに応じて賢くレコメンドするアシスタントを実現しました。

## 3. コワーク授業および開発を通じた学びと成長

1. **プロダクトのライフサイクル管理:**
   要件定義からDB設計、バックエンド・フロントエンドの実装、そしてテスト、ドキュメントの整理までを一人で完結させることで、Webアプリケーション開発の全貌を体系的に学ぶことができました。
2. **実用性とユーザーエクスペリエンスの追求:**
   単に「動く」だけではなく、多言語表示（ウズベク語、日本語など）や、Leafletマップ、Gemini AIとの対話を通じた「ユーザーが使いたくなる洗練されたデザイン（Glassmorphism等）」を追求したことで、より実践的なUX/UIデザインの視点を得ました。
3. **自己管理とタスク推進力:**
   限られた補講期間（約4週間）の中で、WBSスケジュールを立て、毎日進捗を確認しながら、期限（6月30日）までにすべての提出物を高いクオリティで揃える自己管理能力が身につきました。
